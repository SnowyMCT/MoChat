# MChat

一个 Telegram 风格的**联网**桌面聊天软件：有账号系统、有服务端、消息真的从一台电脑
走到另一台电脑。界面（气泡、表情面板、附件、回复/转发、置顶、搜索、动效）照旧。

* **账号**：注册 / 登录 / 退出登录；登录信息**缓存在本地**，下次打开直接进主界面
  （和 Telegram 一样：登一次就够了）。缓存里存的是**令牌**，不存密码，而且**令牌是加密
  落盘的**（见下面「加密存储」）。
  服务端**默认要求注册邀请码**（自动生成并打在启动日志里，客户端注册框填在「邀请码」那一格），
  登录有频率限制与临时锁定 —— 详见 `server/README.md` 的 §9「安全清单」。
* **加密存储**：客户端本地数据（聊天历史、附件缓存、令牌）**默认全部加密**，数据密钥由
  Windows DPAPI 绑定到当前账号（`mchat/core/atrest.py`）；服务端可配 `--storage-key-file`
  让消息与附件在磁盘上也是密文（令牌一律只存哈希）。**注意这仍不是端到端加密** ——
  服务端进程要处理消息，所以它能读到明文。
* **服务端**：`server/` 目录是完整可部署的服务端（**纯 Python 标准库**，零第三方依赖），
  拷到服务器上 `python3 mchat_server.py` 就能跑；部署细节见 `server/README.md`、
  协议见 `server/PROTOCOL.md`。
* **真聊天**：消息、未读、已读回执、正在输入、图片/文件附件都走服务端，
  多设备（同一账号两处登录）也能同步；掉线了消息**攒着**，联网自动补发。
* **没有演示会话了**：以前打开就有的那五个假会话（王尼玛、天下尼玛是一家…）**全部删掉**，
  现在打开是空的，会话由你自己在服务端上建（左栏「＋」找人开聊 / 建群）。
  （那些示例数据搬到了 `tests/seed.py`，只服务于回归测试，不会出现在程序里。）

原来那套 **Base64 / AES-256 安全文本转换器**收进了聊天窗口左上角的 **「工具箱」** 按钮
（快捷键 `Ctrl+T`），当一个小功能保留下来，交互和动效一点没丢。

## 运行

### 1. 先起服务端（自己电脑上试就直接跑本机）

```bash
# 本机自测（数据落在 server/data/）
.venv/Scripts/python.exe server/mchat_server.py --host 127.0.0.1 --port 8765

# 服务器上（部署到公网见 server/README.md：systemd / 防火墙 / HTTPS 反代）
python3 server/mchat_server.py --host 0.0.0.0 --port 8765 --data /var/lib/mchat
```

### 2. 再开客户端并登录

```bash
# 方式一：项目自带 venv（依赖已装好）
.venv/Scripts/python.exe main.py

# 方式二：用 uv 按 pyproject.toml 装依赖后运行
uv run main.py
```

启动时：**本地有登录令牌就直接进聊天窗口**（并顺手向服务端确认一次令牌还有效）；
没有（第一次用、或刚点过退出登录）就显示**登录窗口** —— 填服务器地址
（本机就是 `http://127.0.0.1:8765`）、点「注册」建个号，或者用已有账号「登录」。
勾着「记住我」（默认）就把令牌写进 `%APPDATA%\MChat\MChat\account.json`，
下次不用再登。想换账号：左栏底部那行「账号 · 已连接」右边的**退出图标**。

两个人要真的聊起来：**两台机器都填同一个服务器地址**，各自注册一个账号，
其中一个在左栏「＋」里搜对方的用户名，点一下就能开聊（对方那边会话会自动出现）。

## 界面长什么样

- **左栏**：会话列表（头像 + 名字 + 摘要 + 时间 + 未读徽标）、搜索框、主题切换。
  置顶会话排在最前（名字后面标 📌），摘要按宽度自动省略号截断。
  **在会话上点右键**可以置顶 / 免打扰 / 标记为未读 / 清空这个会话的历史（见下）。
- **左栏头部那几个按钮**：「工具箱」（原转换器）、**「＋」新建会话**（搜人开单聊 / 勾人建群）、
  「齿轮」设置。**左栏底部**是主题切换 + 一行状态小字（`账号名 · 已连接 · host`，
  掉线时变成 `离线，N 条待发 · 正在重连 host`）+ 一个**退出登录**图标（点它会二次确认）。
- **第一屏是登录**：没有本地登录缓存时先出登录/注册窗口；有缓存直接进主界面。
- **一开始是空的**（没有任何演示会话）：点「＋」找人开聊，或者让对方先给你发消息
  —— 新会话会自己冒出来（服务端推的）。
- **右栏**：聊天头部（头像、名字、"在线 / N 位成员 / 正在输入…"）、消息区（气泡 + 日期分隔条）、
  输入栏（表情、自动增高输入框、发送按钮）。
- **发出**的消息靠右（亮色主题是 Telegram 那种浅绿气泡，暗色是深蓝），带头上的 ✓ / 已读 ✓✓；
  **收到**的消息靠左，群里还会显示发送者名字。
- 打开一个会话会先显示本地缓存的历史（**断网也能翻**），再从服务端补最新的
  —— 时间线是"今天 / 昨天"的真实日期分隔。
- 主题：亮色 / 暗色 / 跟随系统，选择会被记住。
- **分界线**：左右两栏之间那条竖线可以直接拖动，改会话列表的宽度（220–460px，窗口变窄时
  上限会自动让步，保证聊天区不被挤没）；鼠标悬停/拖动时竖线会高亮变粗，**双击还原默认 296px**，
  拖出来的宽度和主题一样会被记住，下次打开还在。
- **表情面板**：输入栏左边的笑脸点开就是 Telegram 那样的表情面板（分类 + 搜索 + 最近使用），
  详见下面的「表情面板」一节。
- **图片与文件**：输入栏左边的回形针可以发图片/文件（也是 `Ctrl+V` 直接粘截图），
  详见下面的「图片与文件」一节。
- **气泡右键菜单**：回复 / 复制 / 置顶 / 转发 / 选择 / 删除（删除是**本地删除**：谁发的都能删，
  不是撤回，对方设备上仍然看得到），
  详见下面的「气泡右键菜单」一节。
- **批量操作**：菜单里点「选择」进勾选模式（**也可以按住左键在消息区划过去直接多选**），
  勾完可以**逐条转发**或**合并成一条转发**，
  也可以批量删除（同样是本地删除，谁发的都能删）。
- **设置区域**：左上角齿轮（或 `Ctrl+,`）打开，主题 / 文字大小 / 界面动效 / 数据统计都在里面，
  改一下立刻生效，详见下面的「设置区域」一节。
- **没有 ⋮「更多」菜单**：侧栏头部与聊天头部原来各有一个三点按钮，都删掉了。它里面每一样东西
  都有更直接的入口（工具箱 / 表情 / 设置 / 搜索都有按钮或快捷键，历史统计与动效开关在设置区域里），
  所以这是"少绕一层菜单"，不是"少了个功能" —— 见「实现上的几个坑」里那条同名说明。

交互细节：`Enter` 发送、`Shift+Enter` 换行、`Ctrl+T` 开工具箱、`Ctrl+F` 聚焦搜索、
拖动分界线改宽度（双击还原）、`Ctrl+E` 开关表情面板（`Esc` 也能关）、`Ctrl+V` 粘图片当附件、
`Ctrl+,` 开设置。
`Ctrl+Shift+F` 开全局搜索；气泡上右键可以加表情回应、回复、复制、置顶、转发、删除（本地删除）。
- **本地历史**：消息写进 SQLite（`%APPDATA%\MChat\...\mchat.db`），关掉再打开还在；
  全文检索走 FTS5 索引，2 万条实测检索 13ms。
- **按会话搜索**：聊天头部的放大镜（或 `Ctrl+Shift+F`）只搜**当前会话**的消息，
  点一行跳过去并高亮那条气泡；顶部「仅当前会话 / 全部会话」可以随时放宽范围，
  换会话时范围自动跟着走。想一上来就跨会话找，用搜索窗口里的「全部会话」那一档。
- **草稿**：切走会话时没发出去的话自动存起来，列表里标成红色「草稿：…」，切回来还在。
- **表情回应**：气泡右键有常用表情（或「更多表情…」从面板里挑），点一下加、再点撤；
  自己点过的胶囊会高亮。
- **删除消息（本地删除，不是撤回）**：谁发的都能右键删（红色二次确认，默认停在「取消」），
  气泡、内存、库三处一起清；对方设备上仍然看得到 —— 这是"我这边不看了"，不是撤回。

## 表情面板（802 个表情，全部本地，不联网）

点输入栏左边的笑脸（或 `Ctrl+E`）展开，面板夹在消息区和输入栏之间 —— 展开时**把消息区顶上去**，
不是浮层盖住消息：

- **533 个文字表情 + 269 面旗帜 = 802 个**，分 8 类：表情 / 动物自然 / 食物饮品 / 活动运动 /
  旅行地点 / 物品 / 符号 / 旗帜，底部那排图标就是分类（最左边是「最近」）。
- 格子按面板宽度**自动排满**（拖动左右分界线改变宽度时会跟着重排）。
- **搜索中英都行**：`笑`、`cat`、`rocket` 都能搜，关键词表是中英混排的；把表情本身粘进搜索框
  也能精确定位它。旗帜还能按**国名**搜：`中国`、`香港`、`japan`、`cote`（自动忽略重音）都行。
  清空搜索回到原来的分类。
- **最近使用**：用过的表情排最前，最多记 24 个，写进 `QSettings`，下次打开还在。
- 点表情**不会把焦点从输入框抢走**（格子是 `FocusPolicy.NoFocus`），可以连着插好几个；
  插入位置就是输入框里的光标处。
- 文字表情用的是 Unicode 字符 + 系统彩色字体（Windows 是 Segoe UI Emoji）；**旗帜走图片**：
  Windows 的 Segoe UI Emoji 不画国旗，只会渲染成两个字母（"CN"），所以旗帜是
  `mchat/assets/flags.png` 这张本地精灵图里切出来的（259 个两字母旗 + 10 面特殊旗：
  彩虹 / 跨性别 / 海盗 / 英格兰 / 苏格兰 / 威尔士 / 格子旗…）。字符在这两种情况下都只是
  "查槽位用的 key"，和 Telegram 的做法一致。
- **程序运行期间一次网络请求都没有**：精灵图和关键词表都已经生成好放在仓库里。
  只有重新生成素材的 `tools/build_flags.py` 会联网（跑一次就够，见下）。

### 旗帜在消息里也是图片

面板只是入口 —— **凡是"消息文本"出现的地方旗帜都是图片**：

- 气泡正文、输入框、会话摘要（侧栏每一行）；
- 聊天区顶部的**置顶横幅**、输入栏上方的**回复条**、气泡里的**引用块**；
- **合并转发**卡片那一行摘要、"查看聊天记录"窗口里逐条正文；
- **搜索结果**的命中片段。

（转发窗口那种 `QPushButton` 行没法渲染富文本，是唯一的例外。）

实现上只有一条路：`mchat/ui/flag_text.py` 的 `to_display(text) -> (payload, 是不是富文本)`，
**新增任何"把消息文本塞进 QLabel"的地方都要过它** —— 以前只在气泡和侧栏做了转换，
于是置顶横幅里一直是 "JP/US" 字母（用户一处一处报出来的）。

- 存储 / 发送 / 搜索**永远用原来的字符**（core 层和传输层完全不知道图片的存在）；
  显示前把字符换成 `<img src="file:///…/flags/048.png">`，从输入框取文本时再按 URL
  反查回字符。所以除了面板用的精灵图，还生成了 `mchat/assets/flags/000.png…` 逐张 PNG
  （Qt 富文本的 `<img>` 只按 URL 取"一个文件"，喂不了精灵图里的一格）。
- 富文本化之后 `QLabel.text()` 是 HTML —— 需要"原文"的地方（复制、引用跳转、测试断言）
  都另存一份原串并用访问器取（`bubble.text()` / `quote.text()` / `card.preview_text()`…）。
- 输入框为此从 `QPlainTextEdit` 换成了 `QTextEdit`（只有 `QTextDocument` 能内嵌图片），
  并用 `setAcceptRichText(False)` 挡住外部粘进来的富文本格式；粘贴文本会走同一条
  "旗帜变图"的路。
- **取文本必须自己走文档**：`toPlainText()` 会把图片变成 `U+FFFC`（对象替换符），
  直接发出去消息内容就废了 —— `MessageEdit.message_text()` 按 `U+FFFC` 的位置把图
  换回字符。
- 只有**含旗帜**的消息才走富文本，其余仍是纯文本 —— 消息里写 `<b>粗</b>` 照样原样显示，
  不会被当标签执行（有回归测试盯着）。
- **截断不会切出"半面旗"**：旗帜是两个 regional indicator，切在中间剩下半个会被字体画成
  一个字母方块。`core.models.ellipsize()` / `strip_partial_flag()` 统一收尾（会话摘要 42 字、
  回复引用快照 42 字、合并转发摘要 32 字、侧栏按像素省略号），UI 侧的 `flag_text.truncate`
  只是它的代理 —— 实现只有一份。

### 旗帜素材怎么来的

```bash
# 只有这一步需要联网；素材生成后程序完全离线
.venv/Scripts/python.exe tools/build_flags.py
```

它会抓 Twemoji 的 72×72 旗图拼成 16 列精灵图，再从 Unicode CLDR 的
`cldr-localenames` 取中英国名做关键词（顺手折叠重音、去掉 `St.`/括号这类噪音）。
下载缓存在 `.flag_cache/`（已 gitignore），重复跑不会重新下载。

- 旗图：**Twemoji（jdecked/twemoji），CC-BY 4.0**；国名：Unicode CLDR，Unicode License。
  署名与替换方式见 `mchat/assets/README.md`（想换素材集只要替掉图再跑一次脚本）。

## 图片与文件（图片消息 / 文件消息，`mchat/ui/attach.py`）

输入栏最左边的**回形针**点开有两个入口：**图片…** / **文件…**。
选中的东西不会立刻发出去，而是先挂到**输入栏上方的「待发送条」**里
（缩略图或文件图标 + 名字 + 类型·大小 + ✕），你可以再写一句配文，`Enter` 一起发出去 ——
和 Telegram 的节奏一致。

- **图片消息**：气泡里画等比缩放到 300×300 以内的缩略图（原图不动），点一下用系统看图器打开；
- **文件消息**：气泡里是一张文件卡片（矢量文档图标 + 文件名 + `PDF 文件 · 865 B`），
  点一下用系统默认程序打开，右键菜单里还有「打开所在文件夹」；
- **粘贴截图**：截图工具 / 浏览器里复制一张图，在输入框直接 `Ctrl+V` —— 图片先落到本地库
  旁边的 `clipboard/` 目录存成 PNG，再作为附件走**和"选文件"完全同一条路**；
- **纯附件消息**是合法的（不写配文也能发），会话摘要显示 `📷 照片` / `📎 文件名`；
- **文件丢了也不崩**：图片读不出来时气泡降级成一行「图片不在本地了 + 文件名」，
  文件卡片照常显示存下来的名字和大小；点开缺失的附件会给红字提示，而不是静默失败；
- **附件按会话存**：选好附件后切到别的会话，待发送条是干净的（和草稿同一套逻辑），
  切回来附件还在 —— 不会出现"在 A 会话选的文件发到了 B 会话"。

数据层只记**路径 + 名字 + 大小**（`core/models.Attachment`，落库时序列化成一列 JSON），
不上传、不搬运：单机演示没有服务器，文件就待在原地。接真网络时这一层换成"先上传拿到远端
id、再把 id 随消息发出去"，界面不用改（和传输层是同一个思路）。

演示数据里自带两条附件消息（一张图片 + 一个 PDF），素材由 `tools/build_demo_assets.py`
用 QPainter 现画、提交在 `mchat/assets/demo/` 里（不联网、无第三方许可）—— 打开程序就能
看到这两种气泡长什么样，不用先自己找图。王尼玛的第一次自动回复也会**带回一张图**，
所以"收到别人发来的图片"这条路径在本机就能跑通。

检索**按附件名也能命中**：FTS 索引的那一列是「正文 + 附件文件名」
（`messages.search_text`，VIRTUAL 生成列，磁盘上不存第二份），所以别人丢进来一个
「评审材料-v3.pdf」，搜「评审材料」就找得到 —— 见下面的「本地历史」一节。

## 会话内置顶（"仅我可见 / 双方可见"，联网版）

气泡右键 →「置顶」会问一句"要不要也给对方置顶"：

- **仅我可见**（默认）：只有自己这边看得到横幅，**不会**发任何请求 —— 服务端压根不知道；
- **双方可见**：走服务端（`POST /api/conversations/<id>/pin`），会话里**所有人**立刻收到
  `pin` 事件并跟着置顶/取消 —— 对方那边横幅会显示"双方可见"，谁置顶的也写在提示里。
  对方**取消**了同一条，自己这边也会跟着撤（服务端才是"双方可见"的权威）。
- 一个会话可以置顶**多条**，横幅上用 `‹ ›` 翻；
- 断网时点的"双方置顶"会**排队**，一联上就自动补发（服务端幂等，重复发也不会出问题）；
- 对方置顶的那条哪怕在更早的历史里、本地还没拉到，也能正常显示 —— 事件里带了那条的
  **快照**（`message`），收到就先并进本地。

## 气泡右键菜单（回复 / 复制 / 置顶 / 转发 / 选择 / 删除）

在任意气泡上点右键（图片、文件卡片上也算）弹出来的菜单：

| 菜单项 | 行为 |
| --- | --- |
| **回复** | 被回复的那条会变成输入栏上方的「回复 XX：摘要」条；发出去的消息气泡顶上多一块**引用块**，点引用块直接跳到原消息。切会话时待回复的那条按会话存着（切回来还在） |
| **复制** | 复制正文；纯附件消息复制文件名；既没正文也没附件就明确提示（不静默失败） |
| **置顶** | 参考 Telegram：置顶时选**「仅我可见」**还是**「对方也置顶」**（菜单里就是两个选项）。会话内**可以同时置顶多条**，每条各自带这个标记；已置顶的那条显示「取消置顶（当前：仅我可见 / 双方可见）」，点了也只摘它自己 |
| **转发…** | 打开转发窗口（见下） |
| **选择** | 进勾选模式（见下）。选择模式下右键不再弹菜单 —— 那时点/右键都是"勾选/取消" |
| **⚠ 删除这条消息** | **本地删除，不是撤回**：谁发的都能删（含对方发来的），只删本机这份记录，对方设备上仍然看得到。红色确认框，批量时列明要删哪几条 |

### 批量选择与两种转发

点「选择」后：每条气泡外侧多一个**圆勾**（收到在左、发出在右），点气泡任意位置就是勾选/取消，
输入栏上方出现**批量操作条**「已选 N 条 · 转发 / 删除 / 取消」（`Esc` 也能退出）。
勾选状态在气泡上是一圈主题色描边，和勾是同步的（都走动态属性 + repolish，不是逐帧改样式）。

**圆勾本身也能点**（点勾就是勾上/取消这一条）：它以前挂着 `WA_TransparentForMouseEvents`
（想当然地以为"点在勾上等于点在气泡上"），可勾挂在**行**上、而气泡那层接收层只盖气泡自己 ——
点上去谁也收不到，点了没反应。现在它自己收鼠标，并且按真实按钮的规矩：**按下 + 原地松手**才算一次
点击（划选时鼠标会从勾上划过去，不该顺手翻一下）。

**按住左键在消息区划过去 = 一路选中**（Telegram 那种拖动多选，不用先进选择模式）：
按下的那一条**一定算划中**（进多选这一下会顶布局：批量条出现、气泡右移、消息区矮一截，锚点不能
因此丢），之后划过的每一条都按"起点那条的状态"刷 —— 从没选中的那条划起就是一路选上，从已选中的
那条划起就是一路取消；一条不剩时自动退出多选。**点一下 / 只挪几个像素不算划选**（还是普通点击），
想用鼠标选中文字就按住 **Alt** 再拖。

实现上是给 `QApplication` 装了一个**只看不吞**的事件过滤器（`MessageList.eventFilter`，跟着
`showEvent`/`hideEvent` 挂上摘掉）：事件照常送到原来的控件 —— 文字照样能选、引用块/图片/卡片
照样能点，它只借道记下"按在哪儿、划过了谁"，再按"从按下的点到当前的点的矩形"挑气泡。划选期间
顺手被选中的文字会被收干净（划选是选消息，不是选文字）。划出消息区的部分不算数（这一版没做自动
滚动），滚上去的部分得先把列表滚到那儿再划。

点「转发」打开**转发窗口**（非模态、复用同一个）：列出所有会话，顶部一个
「**逐条转发 / 合并转发**」分段控件，**点一个会话就是确定**：

* **逐条转发**：一条源消息 → 目标会话里一条新消息，每条带一行「➡ 转发自 X」（源会话名）；
* **合并转发**：只生成**一条**消息，气泡里是一张**QQ 那种「聊天记录」卡片** ——
  只有三行：标题「<来源> 的聊天记录」、一行摘要（第一条的「作者：内容」）、
  底部「查看 N 条转发消息 ›」。**内容不塞在卡片里**（塞进去又长又难读）；
  点卡片打开独立的**「聊天记录」窗口**：按聊天气泡逐条列 —— 头像 + 昵称 + 时间 +
  内容气泡（附件写成「📎 文件名」），像真的聊天记录那样能选中复制。

只有一条消息要转发时，那个分段控件**隐藏**（一条没有"合并"可言，隐藏比禁用少歧义）。
转发窗口是**固定尺寸**（`min == max` + `MSWindowsFixedSizeDialogHint`）：它是个"点一行就走"的
小窗口，能拉伸只会拉出一片空白、或者把下面几行挤到窗口外面去。会话行里的标题/摘要按实际宽度
**截成省略号**（`QFontMetrics.elidedText`，视口一变宽就重算）—— `QPushButton` 的文字既不换行
也不省略，摘要一长就会把行按钮撑得比视口还宽，而横向滚动条是关掉的，探出去的部分直接看不见。
行按钮另外挂 `QSizePolicy.Ignored`，从根上保证它不会反过来撑宽滚动区（`overflowing_rows()` 是
常驻断言：右边/下边不许有任何一行探出去）。
转发出来的消息就是**我发的新消息**（落在右边、不触发对方未读），时间戳取"现在"，
附件沿用原来的 `Attachment`（还是只记路径、不复制文件）。转完自动跳到目标会话看结果。

**转发也走传输层**（和手打发送同一条路）：`forward_messages()` 造完消息后会调
`transport.send()`，所以转过去的消息会收到"对方已读"回执（气泡从单勾变双勾）、
对面也会按脚本回一句。少了这一步，转发消息会**永远停在单勾**、对面像没收到一样 ——
合并转发还有第二个坑：它的 `text` 是空的（内容在 `merged_items` 里），而传输层是拿
`text` 判"空消息"的，空消息直接跳过（既不回也不给回执）。所以模型上有个
`Message.send_text`：合并转发返回一句摘要当载荷（`【合并转发】N 条消息`），
纯附件消息仍然返回空串（那种情况由 `attachment` 证明它不是空消息）。

### 数据层（schema v3）

`messages` 加三列、`chats` 加一列，都是可空的默认值，老库打开自动补（见「本地历史」一节）：

```
messages.reply_to       被回复那条的快照（JSON：id/author/preview）
messages.forwarded_from 转发自哪个会话（空 = 不是转发）
messages.merged         合并转发的内容（JSON 数组：author/text/attachment）
chats.pinned_message_id 会话内置顶的 **[{"id":..,"both":..}, ...]**（JSON；空 = 没置顶）
```

引用块存的是**快照**而不是只存一个 id：被引用的那条可能被撤回、或者整个会话被清空，
那时候引用块还得照常显示 —— 存的是"我当时回的是哪句话"。

## 设置区域（`mchat/ui/settings_dialog.py`）

左上角的**齿轮按钮**（或 `Ctrl+,`）打开一个**非模态独立窗口**：
不挡着聊天，边调边看效果。里面是四张卡片，**全部即时生效、没有"确定/取消"**，选择写进 QSettings：

| 卡片 | 内容 |
| --- | --- |
| **外观** | 主题（亮色 / 暗色 / 跟随系统）+ **文字大小**（小 / 标准 / 大 / 特大，四档）+ 字号预览 |
| **界面动效** | iPhone 那种开关，一键开关全部过渡（关掉后所有动效直接落终态，界面语义不变） |
| **数据** | 消息/附件/回应条数与占用、库文件路径、「打开数据目录」按钮 |
| **关于** | 这是本机演示（未联网）、当前传输层、快捷键速查 |

**这个区域本身也带动画**（需求里点名要的），而且全部尊重上面那个动效开关：

1. **打开**：整窗淡入 + 从下方 18px 滑上来，里面的四张卡片再**自上而下错峰**浮现
   （`anim.slide_in()` + `anim.stagger_fade_in()`）；
2. **每张卡片**：鼠标进入/离开时底色与描边**渐变过渡**（160ms，自绘插值 —— 不是 QSS
   `:hover` 那种一帧到位），窗口里所有卡片共用一套时长与缓动；
3. **动效开关**：旋钮滑过去 + 轨道颜色从灰渐变到主题色（自绘 `ToggleSwitch`）；
4. **主题 / 字号的分段控件**：滑块本来就带 220ms 位移动画；切主题还会走全窗口的交叉淡入；
5. **改文字大小**：预览框里的文字**字号动画过渡**到新档位（所见即所得），
   同时主窗口、侧栏、工具箱、搜索窗口的样式表一起重建；
6. **关闭**：淡出后收起。

**文字大小是怎么做到的（一处实现、全局一致）**：界面上的字号几乎都写在 QSS 的 `font-size` 里，
所以 `theme.scale_font_sizes()` 在生成样式表时**把每个 `font-size` 乘一个系数** ——
一处实现，就不会出现"气泡变大了、侧栏没变"这种半吊子效果（系数为 1 时原样返回，
不做任何字符串重写，测试也好断言）。少数**写死在代码里**的字号自己跟着走：
悬浮标签的磅值（`FloatingLabelInput.font_scale()`）和设置窗口里那行预览文字。

## 工具箱（原来那个转换器）

点左上角「工具箱」按钮打开，是一个**非模态**窗口（关掉不影响聊天，重复点复用同一个窗口）：

- Base64 编解码、AES-256-CBC 加解密（SHA-256 派生密钥 + PKCS7 填充）；
- 悬浮标签输入框（170ms 变形动效）、密钥区折叠、一键复制、边框闪红报错、底部提示气泡；
- **切换方式/方向时输入框里的字原样保留**：Base64 ↔ AES-256、编码 ↔ 解码（加密 ↔ 解密）
  来回切，输入都留着、只把上一轮结果收掉，切过去直接回车就能算 ——
  不用再重新粘一遍。清空输入是「清空」按钮（或 `Esc` 只清输出）的事；
- `Ctrl+Enter` 执行、`Ctrl+Shift+C` 复制、`Esc` 清空输出；
- 加密默认 **MChat v1 格式**（`MCH1` + 随机 IV，同一明文每次密文都不同），
  勾选"兼容 Test16 旧格式"则退回固定 IV、可与老程序互通；解密方向两种格式都自动识别。

聊天里还有一条便捷入口：**打开工具箱时，如果聊天输入框里有字、而工具箱里是空的，
那段文字会自动带进去**（带过去时给个提示）—— "把这段拿去处理"本来就是点工具箱按钮最常见的意图。

## 本地历史 / 搜索 / 互动（`mchat/core/db.py`）

聊天记录落在**一个 SQLite 文件**里（`sqlite3` 是标准库，引擎与 FTS5 索引都是原生 C），
位置跟着系统走 —— Windows 是 `%APPDATA%\MChat\MChat\mchat-<用户名>@<服务器>.db`
（**一个账号一个文件**：换个账号登录绝不会看到上一个账号的记录），
设置区域里的「打开数据目录」可以直接跳过去。

联网之后它仍然是**本地缓存**：真正的权威是服务端，本地库负责"打开就能看历史、断网也能翻"。
服务端拉回来的每一条都会顺手落库，所以搜索（FTS5）在离线时照样好使。

```
messages   消息正文（id 主键，conversation_id + ts 有索引）
           attachment  附件的 JSON（path/name/size），没有就是 NULL
                       —— 联网收到的附件可能是 "remote://<附件id>"（还没下到本地）
           file_name   附件文件名（单独一列，给下面的生成列用）
           search_text VIRTUAL 生成列 = 正文 + 文件名 —— FTS 索引的就是它
messages_fts  FTS5 trigram 索引（external content，索引列 search_text，正文不存两遍）
reactions  表情回应（message_id + emoji，记 count 与"是不是我点的"）
drafts     草稿（conversation_id 主键，空串即删除）
chats      会话旗标：置顶 / 免打扰 / 清空过 / 会话内置顶的消息 / **清空时间点**
```

`chats.cleared_at` 是给联网版加的（schema v4）：清空一个会话只是删**本地**这份记录，
服务端那边消息还在 —— 没有这个时间戳的话，下次打开这个会话会把旧消息**再拉回来一次**，
用户会觉得"我删了它又自己长回来了"。记住"清到哪一刻"，比它更早的消息一律不再显示。

几个刻意的取舍：

- **写穿**：仓库每次发消息事件就顺手 upsert 一条（幂等，重复写只是刷新状态），
  不做批量攒批 —— 一条 INSERT 是几十微秒，比"攒批 + 定时刷盘"少一份状态。
  演示数据在启动时整批写回一次，所以库是**完整日志**，连几周前的开场白都能搜到。
- **只取最近**：界面一次只画最近 200 条（`LIMIT`），翻到更早的历史由搜索跳转时
  按需再向库里多要一批 —— 进程里不必常驻全量消息。
- **trigram 分词**：中文按子串命中（"这周要去日本"搜"日本"能中）；`unicode61`
  做不到（实测 0 条）。短于 3 个字符的词 trigram 索引命不了，退化成 `LIKE`（仍是 C 层扫描）。
- **WAL + `synchronous=NORMAL`**：已提交的数据崩了不丢，又不用每条都 fsync；
  退出/启动时 `compact()` 把 WAL 收回主库（2 万条 9.5MB → 4.6MB，耗时 44ms）。
- **附件与"搜文件名"**：`attachment` 一列存 JSON（path/name/size），另有一列 `file_name`，
  而 FTS 索引的是 **VIRTUAL 生成列** `search_text`（正文 + 文件名）。这么绕是为了：搜
  「评审材料」能命中那条"发了个 评审材料-v3.pdf"的消息，而 `text` 仍是干净的正文
  （读回来原样显示、可复制、可转发）；同时因为是生成列，**磁盘上不会把正文存两遍**
  （2 万条实测体积跟以前一样），也不存在"手写代码维护索引串"那种漂移风险。
- **老库自动升级**：打开时 `_migrate()` 用 `PRAGMA table_xinfo` 补齐缺的列 —— v1→v2 补附件那三列
  并重建 FTS 索引，v2→v3 再补回复/转发/合并三列 + `chats.pinned_message_id`（v3 不碰 FTS）。
  老消息一条不丢、检索照旧、新功能立刻可用；再打开一次不会重复动结构
  （`test_migrates_v1_database` / `test_migrates_v2_database` 分别拿真·v1、真·v2 库跑）。
- **会话级旗标**存在 `chats` 表（`conversation_id + pinned/muted/cleared + pinned_message_id`）：
  置顶与免打扰由侧栏右键菜单切换，重启后照旧；`cleared` 是"这个会话被清空过"的标记，用来在启动时
  把重新生成的演示数据里那几条种子消息丢掉 —— 否则上次的清空下次启动就白清了；
  `pinned_message_id` 是会话内被置顶的那条（气泡右键菜单里置顶），启动时如果它指向的消息
  已经不在了（被删/被清空）就从置顶里剔掉，顺手把库里也写干净。

  这一列先后用过三种存法，读的时候**全都认**（``models.pins_from_json``）：
  单个裸 id（v3 第一版）→ 纯 id 数组（"多条置顶"那版）→ 现在
  ``[{"id":..,"both":..}, ...]``（带"给不给对方看"）。既不用加列也不用升版本 ——
  老库打开照样读得出来，写过一次之后就变成新格式；坏 JSON 降级成"没置顶"。
- **清空历史是按会话来的**（侧栏右键菜单里那一项）：只删这一个会话的消息、回应和草稿，
  **其它会话不受影响**；仍然走 `confirm_destructive()` 二次确认（红色按钮 + 默认停在"取消"），
  确认文案里会写明是哪个会话、要删多少条。清完顺手 `compact()` 把文件收小。
- **免打扰**不是只画个月亮图标：未读徽标变灰、不再弹跳，而且**不计进顶部总数**
  （`store.total_unread()` 里就把免打扰的跳过，逻辑只有一份）。
- **危险操作**（删消息、清空某个会话）走 `confirm_destructive()`：红色按钮 + 默认停在"取消"。

实测（`tests/test_db.py` 里的基准，2 万条中文消息，本机）：

```
批量落库 365ms ｜ FTS5 检索 13ms ｜ 取最近 200 条 0.5ms ｜ 占用 240 字节/条（compact 后）
```

搜索窗口（`mchat/ui/search_dialog.py`）**范围默认是"你现在开着的这个会话"**（从哪个会话
进去就搜哪个会话），顶部有「仅当前会话 / 全部会话」分段控件；换会话时范围跟着走，
只有"全部会话"模式不受影响。输入防抖 180ms、最多显示 60 行，点一行就切会话 + 滚动 +
闪一下边框定位到那条消息。会话过滤是拼进 SQL 的 `WHERE conversation_id = ?`
（FTS5 与 `LIKE` 两条路径都支持），不是查完再筛。

## 界面动效（`mchat/ui/anim.py`）

时长与缓动只有一份（`FAST 140 / NORMAL 200 / SLOW 280` + `OutCubic`），七处动效共用同一套函数：
`fade_in` / `fade_out`（收场）/ `slide_in`（整窗滑入）/ `stagger_fade_in`（错峰）/
`cross_fade`（主题交叉淡入）/ `slide_scroll`（滚动滑入）/ `TypingDots`。

- **新消息入场**：**只淡入 + 滚动滑入**，气泡一上来就占最终大小。
  这是被实测逼出来的：最早的写法是"高度 0 长到自然高度 + 淡入"，逐帧量出来三个毛病 ——
  开头 30ms 停着不动、长个儿的时候气泡在行里被反复居中（y 在 `616↔628` 之间来回抖）、
  收尾恢复高度时整条列表跳 48px。根因是**动了几何**：每帧都要重排整块列表。
  现在的做法几何全程不动（表格里的高度恒定 49px、y 从 683 单调滑到 579），
  "从下面滑上来"交给滚动条动画（只改一个整数，绘制层直接平移）。
  只给新到的消息做；初次铺满整屏不做，否则一屏十几条一起动，既卡又晕。
- **"正在输入"**：头部文字后面跟三个跳动的小点（自绘 + 45ms 定时器，隐藏即停，
  不常驻 CPU；相位差做出"追逐"感）。
- **主题交叉淡入**：切主题前先把旧外观抓成一张快照盖上，再让它淡出 —— 不是硬切。
- **未读徽标回弹**：数字变多时用 `OutBack` 弹一下（自绘缩放，不触发重新布局）；
  只对已经在屏幕上的条目弹，首次铺列表不弹，免得太吵。
- **搜索结果错峰淡入**：结果行每行延迟 16ms 依次浮现（延迟累加上限 12 行，60 行也不等半天）。
- **表情回应**：只有新加的那个胶囊淡入，已有的纹丝不动。
- **设置区域**：整窗淡入 + 上滑、四张卡片自上而下错峰、卡片 hover 底色渐变、开关旋钮滑动、
  改字号时预览文字的字号过渡（见「设置区域」一节）。全部尊重动效总开关。

滚动位置上的两处处理（不处理的话消息会跑出视野）：

- **新消息的滑入**：`anim.slide_scroll()` 先把位置垫到"新气泡正好在折线下方"，
  再用 240ms 滑到底。有个坑：追加那一瞬间 `scrollbar.maximum()` **还是旧值**
  （布局要一拍才认出新增的高度），所以终点必须挂 `rangeChanged` 动态修正，
  否则会停在"差一条消息"的地方（实测停在 321/376）。
  没有滚动余量（内容还没满一屏）时**什么都不做**：那时新消息本来就在视野里，硬滚反而一跳。
- **表情面板展开/收起**会改消息区高度，原本贴底的位置就"错位"了：等面板铺开
  （或收完）之后再补一次 `follow_bottom` —— 只在打开面板前就是贴底状态时才补，
  正在翻历史的人不该被拽回来。

另外，**点消息区的空白处会收起表情面板**：在消息区视口上装一个 `eventFilter`
（只对"消息区里的点击"生效，点面板自己不受影响），而且**不吞掉这次点击** —— 该选
文字、该点气泡照常。

三条硬约束（写在这里免得后人再踩）：

1. **动画结束一律摘掉 `QGraphicsOpacityEffect`** —— 留着等于给控件常驻一层离屏合成，
   长列表会明显变卡，也破坏像素级断言。另外**别把透明效果套在 QScrollArea 上**，
   视口会走离屏合成、滚动出现拖影。
2. **可一键关闭**：`anim.set_enabled(False)`（设置区域里的「界面动效」开关，选择记进 QSettings）
   关掉后所有动效**直接落终态**，界面语义不变 —— 测试要像素确定性时也靠它。
3. **删控件前先 `anim.cancel(widget)`**：删除是 `deleteLater`，动画的收尾回调可能才刚跑起来，
   回调里再碰控件，PyQt6 会把 `RuntimeError` 升级成**进程级崩溃**（实测踩过一次，
   清空历史/刷新搜索结果时必现）。

## 真网络是怎么接上去的

界面只依赖传输层的三个动作（`start` / `send` / `poll`），所以"联网"这件事被完整地关在
**一个实现类**里，ui 一行都没改：

```python
class ChatTransport(abc.ABC):              # mchat/core/transport.py
    def start(self) -> None: ...
    def send(self, message: Outgoing) -> None: ...
    def poll(self, now: float | None = None) -> list[TransportEvent]: ...
```

- `NetworkTransport`（`mchat/core/net_transport.py`，真机用的就是这个）：
  `send()` 把消息丢进**发件箱**立刻返回，一条后台线程负责发送 + 长轮询收事件，
  `poll()` 把收到的事件倒给界面 —— 形状和本机演示那个 `LocalTransport` 一模一样；
- 三条必须在联网实现里做对的事：**掉线重发**（消息不丢，重发用同一个 id，服务端幂等，
  不会变成两条）、**断线自动重连**（1s → 2s → 5s 退避）、
  **附件先上传再发**（收到时下到本地缓存，下不动就留着"点一下重试"）；
- 主窗口每 400ms 调一次 `tick()`，把事件喂给 `ChatStore`，界面靠订阅刷新 —— 这条链路没动。
  `ChatStore` 内部有锁，网络线程直接 append 也是安全的；
- **跨端状态一律"服务端存 + 服务端推 + 客户端按事件改"**：在线状态由服务端每几秒扫一遍
  `last_seen`（`_presence_watcher`），一变就推给"跟他有共同会话的人"，界面收到 presence
  就把仓库里的成员状态换掉、刷新小绿点与聊天头部第二行（`MainWindow._apply_presence`）。
  客户端**不自己算**在线、也不在本地"开关式"地改 —— 唯一的例外是"改状态"这件小事，
  它必须走 `ChatStore.set_user_online()`（frozen dataclass 只能换对象，见下面的坑）；
- 登录、拉会话、拉历史、已读回执这些一次性请求走 `mchat/ui/async_call.py`：
  后台线程发请求、**Qt 信号**把结果排队送回主线程（不能直接回调 —— 那等于在后台线程碰界面）。

服务的另一头是 `server/mchat_server.py`：**纯 Python 标准库**写的一个 HTTP 服务，
用长轮询（`/api/sync`）做实时推送。协议见 `server/PROTOCOL.md`，
部署见 `server/README.md`。它能部署在服务器上，也可以就跑在你自己电脑上（局域网/本机自测）。

**别再用 `pyinstaller -F -w main.py`**。那条命令不带任何 data 文件，而素材是**图片/文件本体**
（`mchat/assets/flags.png` + 逐张 PNG，外加 `mchat/assets/demo/` 里演示附件用的那张图片和那个
PDF）：冻结后 `flags.sprite_exists()` / `png_exists()` 全假，界面整体降级成纯文本，而 Windows
的 Segoe UI Emoji 不画国旗、只画成两个字母 —— 于是旗帜全部变成 "CN" "JP"；演示数据里的
图片/文件消息也会变成"图片不在本地了"（踩过一次的坑）。素材必须按 `main.spec` 的
`datas=[('mchat/assets', 'mchat/assets')]` 打进去；而且那条命令会把 `main.spec`
重写成 `datas=[]` 的默认版，所以别拿它当备选。

素材路径是**冻结感知**的：`ui/flags._assets_dir()` 与 `core/assets.assets_dir()` 都先看
`sys._MEIPASS`（PyInstaller 的解包目录，onefile 是临时目录、onedir 就是 exe 旁边，层级与源码
一致），那里没有才落回源码树。onefile / onedir 都不用改代码。

`tools/build_exe.py` 做四件事：① 检查素材齐不齐（旗帜 + 逐张 PNG + 两个演示附件，缺就立刻报，

解释器打出来（**用哪个解释器打包就冻结哪个 PyQt6**）；③ 跑 `pyinstaller main.spec`；
④ 读 PyInstaller 自己写的 `build/main/PKG-00.toc` 清单，核对 `mchat/assets` 下的文件
真的都进了包（含演示附件），对不上就非 0 退出。

`tests/test_flags.py` 里有三条断言盯着这件事（冻结路径解析、素材路径必须是绝对路径、
`main.spec` 必须带素材），`tests/test_attachments.py` 里也有一条盯着演示附件素材在不在
（`test_demo_assets_exist_on_disk`）—— 再把 `pyinstaller -F -w main.py` 之类改回来会当场变红。

**打包后想确认"旗帜真的画成图了"**，跑一次自检探针（不弹窗、不抢焦点，退出码 0 就是好的）：

像素** → 富文本里的旗帜真的是 `<img>` 且图片文件存在 → 面板格子的图标不是退回画字符、相邻两面

两个界面套件是脚本式的（`main()` 返回失败项数），文件末尾各挂了一个 `test_*_suite()`
包装，所以 `pytest tests` 与直接运行跑的是同一批断言。

界面测试用 `WA_DontShowOnScreen` 让窗口"显示但不出现"：布局与绘制走真实平台（中文渲染正常），
屏幕上不会弹窗、不抢焦点；截图落在 `artifacts/`（亮/暗主题的聊天窗口 + 附件 + 工具箱）。
无显示器的环境可加 `QT_QPA_PLATFORM=offscreen`（此时中文会变成方块，只适合跑断言）。

界面测试里几个"不能真的做"的动作都换成了替身：确认弹窗走 `confirm=` 注入、文件选择框走
`filedialog=` 注入（`QFileDialog` 是模态窗口，无头跑会一直等）、"用系统程序打开附件"把
`QDesktopServices` 换成记录器（否则测试会真的弹出资源管理器和看图器）。

`tests/ui_probe.py` 是两个界面测试共用的工具：`pump()` 推进事件循环、
`glyph_pixels()` / `widget_pixel()` 按 DPR 从窗口截图里取像素（验"字色是否可读"、
"分界线到底画没画出来"这类只能靠像素说话的问题）、`colorful_pixels()` 数彩色像素
（验表情是不是真的用彩色字体画出来了，而不是豆腐块）、`drag_split_handle()` /
`double_click_handle()` 发带真实全局坐标的鼠标事件，用来端到端模拟拖分界线。
`wait_for(app, predicate)` 则是**动画断言的正确姿势**：一边跑事件循环一边等条件成立，
而不是"睡固定时长 + 卡阈值" —— 后者在机器慢一拍时会在动画尾巴上偶发失败（同一处抖过
两次、约 1/30 概率），换成它之后连跑十几轮都稳。

**切主题之后抓像素/截图，要先等 `theme_overlay()` 变 None**：主题交叉淡入是"把旧外观抓成
一张快照盖在窗口上淡出"，淡到一半时那层快照是半透明的，会把深浅两头一起拉平 ——
表现是像素断言偶发 `深=0 亮=0`（看着像"字色坏了"，其实是快照还盖着）。
`shoot()` 里也加了这道等待，否则 artifact 可能拍进旧外观。

**还有一类偶发失败来自"睡一会儿再看状态"**：设置区域那条"打开时整窗在动"原本是
`pump(100)` 之后查 `is_entering()`，机器忙的时候这 100ms 的 pump 实际可能跑了 300ms，
动画早跑完了 —— 改成 show() 之后**立刻**查（动画是同步启动的），把时间假设从断言里拿掉。

同一条纪律在别处也翻过车，凡是"动画/布局改完就断言"的地方统一用 `wait_for`：
密钥区折叠（`maximumHeight() == 0`）、表情格子按面板宽度重排（列数）都吃过亏 ——
机器负载高时动画尾巴会拖过固定 pump 的时长，读到的是上一轮的状态。
（这两处就是本轮加上输入框保留逻辑后暴露出来的：不是新代码的问题，是老断言的时间假设太紧。）

## 实现上的几个坑（都已处理）

- **构造期事件**：`setCursor` / `setMinimumHeight` 会在 `__init__` 中途派发事件，此时处理函数若访问
  尚未创建的属性，PyQt 会在 C++ 虚函数里抛异常并直接 `abort()`（没有 Python 报错栈）。
  自绘组件因此都有 `_ready` 闸门，且事件过滤器安装前先给 `self._field` 赋值。
- **动态控件必须显式 `show()`**：父控件已显示后再创建的子控件默认隐藏 —— 切换算法时新建的分段按钮、
  刷新会话列表时新建的条目，不 `show()` 会整片消失。
- **别指望 `deleteLater()` 立刻回收**：`DeferredDelete` 只在事件循环回到主层级时处理，
  旧控件会和新控件叠着画。改法是先 `hide()` + `setParent(None)` 再 `deleteLater()`。
- **动态属性的 QSS 要手动 repolish**：会话条目的选中态用 `[selected="true"]` 选择器，
  改完属性必须 `style().unpolish/polish` 才会重新匹配，否则高亮不变。
- **对话框不继承主窗口样式表**：`QDialog` 是顶层窗口，得自己 `setStyleSheet(build_qss(p))`，
  所以工具箱由主窗口在切主题时显式 `apply_palette()`。
- **分界线由自己画，所以侧栏的 `border-right` 挪走了**：竖线如果由侧栏和分界线各画一半，
  主题切换、悬停高亮的时机对不上就会露出双线或错位。现在 `#sidebar` 不画右边框，
  `SplitHandle.paintEvent` 一次画完"底色 + 中缝"（默认边框色、悬停主题色、拖动加粗）。
  另外侧栏宽度用 `setFixedWidth` 而不是 `setMinimumWidth`：拖动时只有聊天区在伸缩，
  宽度所见即所得，不会因为窗口略窄被布局"匀"回去。
- **未读的先后顺序**：`ChatStore.receive()` 先累加未读再入库 —— 入库会通知界面，
  界面发现"这条会话正开着"会立刻清零；顺序反了未读会残留。
- **表情面板是"布局里的控件"，不是弹窗**：`Qt.Popup` 那类浮层在
  `WA_DontShowOnScreen` 的窗口上根本没法做无头验证（另一个顶层窗口，收尾还容易挂住），
  而且会盖住消息。现在面板就夹在消息区和输入栏之间，展开动画只改 `maximumHeight`，
  消息区自然被顶上去 —— 既能被测试，又和 Telegram 的行为一致。
- **表情格子必须 `NoFocus`**：QToolButton 默认点击会拿焦点，用户点两个表情就得再点回输入框。
  格子设成 `FocusPolicy.NoFocus` 后，焦点留在输入框/搜索框，可以连点。
- **`autoExclusive` 的按钮不能程序化取消勾选**：搜索状态下要让所有分类按钮都"未选中"，
  直接 `setChecked(False)` 会被 Qt 挡回去；得先 `setAutoExclusive(False)`、改完再打开。
- **旗帜只能走图片**：Windows 的 Segoe UI Emoji 不画国旗（渲染成 "CN" 两个字母），
  英格兰/苏格兰/威尔士那种 tag 序列更是几乎没字体支持。所以旗帜做成一张本地精灵图，
  按 `字符 -> 槽位` 查坐标切图（`flags.cell_rect`）—— 和 Telegram 一样，字符只是 key。
  另外**素材是生成物**：`tools/build_flags.py` 跑一次产出 `flags.png` + `flags.py`，
  程序运行时不联网；构建脚本里的正则/反斜杠务必用编辑器写（shell heredoc 会把 `\b`
  变成真的退格符，正则静默失配）。
- **富文本里判断"是不是图片"不能只看 `charFormat().isImageFormat()`**：图片后面插入的
  文字（甚至 `QPlainTextEdit → QTextEdit` 的 `setPlainText`）会**继承图片的字符格式**，
  于是纯文字片段也报 `isImageFormat() == True`，取文本时就把它当成图片、返回空串。
  判据要跟 Qt 自己对齐：真图片在 `toPlainText()` 里是 `U+FFFC`（对象替换符）。
  另外插图后要 `cursor.setCharFormat(QTextCharFormat())` 抹掉图片格式，否则后续输入的
  字符都带着它。这两条合起来才是"输入框里能插图又取回原文"。
- **`QMenu.exec()` 会阻塞，别在测试里触发它**：右键菜单"能不能弹出来"没法在无头测试里
  验证（exec 会一直等用户点），正确做法是把菜单构造拆成 `_build_conversation_menu()` /
  `_build_bubble_menu()` 这样的方法，测试直接拿到 `QMenu`、按文字点名 `QAction`
  再 `trigger()` —— 覆盖的是同一条代码路径。想看样式就 `popup()`（不阻塞）+ `grab()`。
  反过来，**别在测试里真的发一个会走到 `exec()` 的事件**：会挂死到超时（实测踩过一次，
  10 分钟才被 timeout 掐掉）。非要测"右键那一行会请求弹菜单"这条链路，就先
  `signal.disconnect(handler)` 摘掉主窗口的处理器，测完再接回去。
  （侧栏头部和聊天头部那两个三点按钮连同它们的"更多"菜单已经删掉了 —— 见下面那条
  「删掉一个入口时，先把它的能力搬走」。）
- **"发出去"这件事不止是往仓库里塞一条**：转发消息最初只做了 `store.forward()`，
  结果对面既不回、气泡也停在单勾 —— 凡是"我发出的消息"，都要同时交给传输层
  （`transport.send()`），否则已读回执和对方回复这两条路根本没被触发。
  合并转发还要额外注意：它没有 `text`，得用 `Message.send_text` 给个载荷，
  不然会被传输层当成"空消息"跳过去（见上面「转发」那一节）。
- **探针别对已经显示的真实窗口设 `WA_DontShowOnScreen`**：Qt 会为此重建平台窗口，
  过程中抛出的异常在 C++ 里变成静默 abort（进程直接死、没有 Python 栈，退出码 127）。
  测试里能这么干是因为整棵树本来就在离屏；真机探针里要么别设，要么一开始就别 show。
- **假时钟要和真实时间对齐再发消息**：转发/发送用 `time.time()` 记时间戳，而回复按注入的
  假时钟排期；不对齐时回复的时间戳可能落在消息**之前**，消息顺序就乱了（测试里表现为
  "最后一条不是回复"）。
- **删掉一个入口时，先把它的能力搬走**：侧栏头部与聊天头部原来各有一个 ⋮「更多」按钮，
  点开是同一个菜单（工具箱 / 表情 / 设置 / 发图片 / 发文件 / 搜索 / 历史统计 / 打开数据目录 /
  动效开关 / "把输入框的文字送进工具箱"）。删两个按钮很容易，难的是**确认菜单里没有"只此一家"
  的能力** —— 逐条对过之后只有一条是独有的（跨会话搜索在搜索窗口里自带「全部会话」档；
  历史统计与动效开关已经在设置区域里），于是把它并进 `open_tool()`：打开工具箱时若工具里为空、
  聊天输入框里有字，就自动带过去，且**不覆盖**用户已经敲进去的内容（显式传 `prefill` 仍强制送入，
  老 API 语义不变）。测试里那组断言是专门盯这件事的：两个头部不再有 `more_btn`、相关信号与
  `_build_menu()` 都不存在、`make_icon("more")` 画不出东西，**同时**工具箱/表情/设置/搜索四个
  按钮还在、四个快捷键还在、跨会话搜索与历史统计仍然可用 —— 以后再删入口，测试会直接告诉你
  "能力是不是掉了"。
- **列表里别动控件几何**：想让新消息"冒出来"而去动画它的高度，代价是每帧一次整块
  列表重排 + 气泡在同一行里被反复居中（实测 y 在 `616↔628` 来回抖），收尾恢复
  高度时还会整体跳一下 —— 观感就是"卡一下"。正确做法：**控件一上来就占最终大小**，
  只用透明度做淡入，"从下面滑上来"改成滚动条动画（只改整数、不做布局）。
  要动几何时也得记住：追加那一刻 `scrollbar.maximum()` 还是旧值，滑动终点必须挂
  `rangeChanged` 动态修正。回归用例要先堆出滚动条、再逐帧采样"高度恒定 + y 单调"
  （用 `mapTo(viewport, …)`，别用 `widget.y()`——那是行内相对坐标，恒为 0，断言等于没断言）。
- **PyQt6 动画的两个致命坑（都把进程干崩过）**：① `QTimer.singleShot(0, 上下文对象, lambda)`
  这个三参数重载 + lambda 会崩，换成两参数版就没事；② 在 `QAbstractAnimation.finished` 槽里
  当场 `setGraphicsEffect(None)` 也会崩（推迟到下一轮事件循环再摘）。③ 控件被 `deleteLater`
  之后动画回调再碰它，`RuntimeError` 会被升级成致命错误 —— 所以删之前先 `anim.cancel()`。
  这类崩溃的排查姿势：`python -X faulthandler` 直接给出崩溃时的 Python 调用栈。
- **SQLite 的取舍（都踩过）**：中文子串检索必须用 FTS5 的 `trigram` 分词（`unicode61`
  对"这周要去日本"搜"日本"是 0 条）；`trigram` 命不了 3 字符以下的关键词，得留一条
  `LIKE` 兜底；外部内容表（`content='messages'`）要靠触发器维护，**UPDATE/DELETE 都要写
  `'delete'` 那条特殊插入**，否则索引会和正文漂移；`VACUUM` 自己会往 WAL 里写一大堆页，
  所以 **先 VACUUM 再 `wal_checkpoint(TRUNCATE)`** 才收得干净（反过来白干）。
- **生成列（`GENERATED … VIRTUAL`）的两个坑**：① `PRAGMA table_info` **不列生成列** ——
  用它判断"列在不在"会把已有的 `search_text` 当成缺列，于是再 `ALTER TABLE` 一次直接报
  `duplicate column name`（用 `PRAGMA table_xinfo`，它才含生成列/隐藏列）；② 生成列
  **不能出现在 INSERT 的列清单里**（`_UPSERT` 里只写 `text` / `attachment` / `file_name`），
  但触发器里读 `new.search_text` 是允许的（INSERT/UPDATE/DELETE 三种都实测过）。
- **切会话时"待发送的附件"必须跟着会话走**：附件不是全局状态，而是"那个会话里正在组织的
  一条消息"的一部分（和草稿同一个道理）。不处理的话，用户在 A 会话选好文件、切到 B 会话直接
  回车，文件就发给了 B —— 界面上还完全看不出错。现在切会话时把它记到会话名下
  （`MainWindow._stash_attachment`），测试里有一条专门盯着"切走是干净的、切回来还在"。
- **剪贴板里的图片要先落地成文件**：消息、库、传输层、缩略图缓存都只认"一个路径"，
  所以 `insertFromMimeData` 里发现剪贴板有图就抛信号，由主窗口存成 PNG 再当普通附件 ——
  这样"粘贴的图"和"选的文件"之后走的是同一条路，只有一处需要维护。
  （判断顺序上**图片优先于文本**：有些来源会同时给 `image` 和 `text`。）
- **"文字大小"只有一处实现**：所有 QSS 的 `font-size` 在生成样式表时统一乘系数
  （`theme.scale_font_sizes()`），改字号 = 重建一次全窗口的 QSS。这样不会漏、也不会出现
  "气泡大了侧栏没大"。代价是**写死在代码里的字号得自己跟**（悬浮标签的磅值、设置里的预览
  文字），漏掉哪个哪就显小 —— 测试里两条断言分别盯着这两处。
- **代码里改字号后要自己撑高度**：设置窗口那行预览文字的字号是用 `setFont()` 逐帧改的，
  布局只在 polish 时量一次、不认这个变化，第一版就被上下裁掉（截图里一眼看出来）。
  正解是按 `QFontMetrics.boundingRect(..., TextWordWrap, text)` 算出**换行后的真实高度**
  再设最小高度，并且在 `resizeEvent` 里重算 —— 不要猜行数。
- **`QPropertyAnimation` 的目标属性名必须和 `pyqtProperty` 的名字一致**：开关的旋钮是
  `progressValue` 这个属性驱动的，写错名字（比如 `b"progress"` 而属性叫 `progressValue`）
  时 Qt 只会静默不动，界面看起来"就是没动画"，没有任何报错。
- **在 C++ 虚函数里抛异常 = 进程静默死亡**：`ToggleSwitch.set_checked()` 里少写了一句
  `from . import anim`，`anim.is_enabled()` 抛 NameError；因为它是在 `mouseReleaseEvent`
  这个 C++ 虚函数里被调用的，PyQt 直接 `abort()` —— **没有 traceback、没有 py 栈、
  `-X faulthandler` 也什么都打不出来**，只有一个退出码 127。定位方法是"每个变体一个进程"
  的最小复现脚本 + 逐行打印（打印到第 7 步就断，答案就落在第 7~8 步之间）。
  教训：凡是在 `paintEvent` / `*Event` / 动画回调里调用的东西，先确认 import 都在。
- **危险操作的确认弹窗要能注入**：`QMessageBox.exec()` 会开一个嵌套事件循环，
  无头测试里会直接挂住。所以主窗口收 `confirm` 回调（默认弹真窗），测试注入固定答案；
  同理**本地库也要能注入**（`log=`），否则跑一次测试就把用户 `%APPDATA%` 里的真实历史
  改了一遍 —— 这两条都是"可测试性倒逼出来的设计"。
- **富文本图片只能按 URL 取文件**：`<img src="…">` 支持 `file:///` 路径（`QLabel`、
  `QTextEdit` 都行，不用注册 QTextDocument 资源），但喂不了精灵图里的一格 —— 所以
  面板用精灵图、文本侧另生成逐张 PNG。Windows 路径里的盘符冒号别让 `quote()` 编码成
  `%3A`；路径带空格/引号时必须编码（`quote(path, safe="/:")`）。
- **QSS 只写背景不写颜色 = 暗色主题下的黑字**：`QTextEdit#composerInput` 原来只设了
  `background: transparent`，Qt 就把字色退回系统默认调色板（黑），落在深色输入栏上几乎看不见。
  凡是在 QSS 里给文字控件设了背景，就顺手把 `color`（以及 `selection-*`）写上；
  组件侧再用 `QPalette` 设一遍 `Text` / `PlaceholderText` 兜底。测试用像素断言守着
  （`glyph_pixels()`：暗色下最亮像素必须够亮、最暗不低于底色）。
- **截图断言要乘 devicePixelRatio**：高分屏（本机 DPR 1.75）下 `grab()` 出来的是设备像素，
  用逻辑坐标去 `copy(QRect)` 会裁到毫不相干的区域，测出来的数字全是错的。
- **逐帧不做 QSS 解析**：动画只改字号与 `QPalette` 颜色；颜色令牌变了才重建样式表。
- **自绘控件不嵌套布局**：标签、滑块、字段的几何全部手算，动画期间不会触发布局回流。
- **frozen dataclass 不能就地改状态（"好友上线了我这边还显示离线"的真凶）**：成员是
  `User(id, name, online, is_bot)` 这种 `@dataclass(frozen=True)`，`member.online = True`
  会抛 `FrozenInstanceError`。单看这一行没什么，但它跑在 `tick()` 这条事件轮询里（Qt 定时器槽），
  异常一冒整条 tick 就断在那儿 —— 服务端推过来的 presence 事件被"读到一半"就没了，表现正是
  "对方上线/下线，我这边状态一直不变"。改状态一律 `dataclasses.replace()` 出新对象
  （`ChatStore.set_user_online()` 一次把他出现的所有会话都换一遍），测试里那条
  "冻结成员翻转"就是回归。教训：**状态对象是 frozen 时，"改一个字段"要当成"换一个对象"来写**。
- **`quitOnLastWindowClosed(False)` 的代价：最后一个窗口关了程序也不退**：为了登录窗口/主窗口
  交替时不会有"零窗口"的瞬间，这个开关是关掉的（见 `launcher.main`），于是主窗口被 ✕ 掉之后
  **谁都不会让 QApplication 退出** —— 窗口没了，进程还挂在资源管理器里（长轮询线程、数据库连接、
  内存全留着）。登录窗口那条路一直有 `_on_login_closed`，主窗口缺一个对等的：
  `MainWindow.closeEvent` 收尾之后发 `closed` 信号 → `Launcher._on_main_closed` 里 `app.quit()`。
  「退出登录」走的是 `logoutRequested` + `hide()`（`hide()` 不触发 `closeEvent`），不会被误伤。
  配套三件事：① 关窗时给发件箱留 1.5 秒（否则"敲完就关"的那句话永远发不出去，而以前进程赖着
  不走反倒"顺手"发出去了）；② 库关掉之后迟到的后台回调直接丢（`_shutdown_done` 闸门），
  不然日志里会刷 `Cannot operate on a closed database`；③ 这件事**只能在子进程里验**
  （判据就是"进程自己退出了"），所以 `test_server.py` 里那条用例会 spawn 一个真进程：
  自动登录 → 开主窗口 → `window.close()` → 断言 `app.exec()` 返回 0 且总耗时正常。
  它以前会一直挂着（用例里 20 秒后自杀报 TIMEOUT）—— 也就是说**这条用例是先看着它红、
  再改代码的**。
